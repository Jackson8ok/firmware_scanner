## 🎯 Phase 4 详细说明（供参考）

### 问题来源

**案例**: ARM Cortex-M 车载控制器固件验收测试

| 检测方式 | 结果 | 风险 |
|---------|------|------|
| **研发 SBOM** | wolfSSL 5.8.4 ✅ | - |
| **二进制指纹** | 0 命中 ❌ | 漏报 67 个 CVE（11 Critical） |

**原因**:
- wolfSSL 静态链接到固件
- 编译时使用了 `-s` 参数（strip 符号表）
- 二进制中无函数名/版本字符串
- 纯字符串指纹法无法识别

### 解决方案

**SBOM 融合架构**:
- 输入：研发 SBOM + 二进制指纹
- 输出：融合结果 + 证据分级
- 证据级别：A（指纹确认）、B（SBOM 声明）、C（仅指纹/版本未知）
- CVE 加权统计：A=1.0, B=0.5, C=0.25

### 为什么是可选功能？

1. **需要研发配合** - 必须提供 SBOM
2. **验收方无 SBOM** - 纯黑盒测试场景用不上
3. **内部价值 > 外部价值** - 主要用于研发自测
4. **未来工作流** - 等待客户接受 SBOM 输入模式

## 📋 验收测试建议

### 必需验证项（Phase 1+3）✅

| 测试项 | 方法 | 预期结果 |
|--------|------|---------|
| 大小写不敏感 | 上传含 `LWIP` 日志的固件 | 正确识别 lwIP 组件 |
| 版本未知标注 | 上传版本未知组件的固件 | 输出 `version: unknown` + 置信度分级 |
| CVE 匹配精度 | 使用标准样本 | CVE 偏差 ≤ 20% |
| 字段完整度 | 检查输出 | cvss/epss/date 非空率 ≥ 90% |

### 可选验证项（Phase 2+4）⚠️

| 测试项 | 方法 | 预期结果 | 优先级 |
|--------|------|---------|:------:|
| SBOM 解析 | 提供 SPDX/CycloneDX 文件 | 正确解析组件列表 | 低 |
| SBOM 融合 | 提供 SBOM + 固件 | 输出 A/B/C 分级结果 | 低 |
| CVE 加权统计 | 检查融合结果 | 加权 CVE 数计算正确 | 低 |

**建议**: 验收时间有限，优先验证 Phase 1+3
