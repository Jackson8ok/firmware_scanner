## 2. 实测数据对比（BCT01 ramdisk 固件，三方基线同 v2.4.1 报告）

### 2.1 扫描流程正确性——已恢复

```
v2.4.1: 解包失败回退到空路径 → Syft 扫描项目目录 → 53 个项目依赖组件 → 394 个错误 CVE
v2.4.2: 7-Zip 成功解包 → 目录组件提取 → 15 个真实固件库组件 → 114 个 CVE（归因正确）
基线：7 个组件（busybox 1.35.0 等）→ 6 个精确 CVE
```

v2.4.2 识别出的 15 个组件均为 ramdisk 真实内容（libgcrypt、libgpg-error、libpcre、libselinux、libcryptsetup、libdevmapper、libpopt、libsepol 等），**项目依赖泄漏已消除**。

### 2.2 性能对比

| 指标 | v2.4.1 | v2.4.2 | 官方声明 | 基线 (grype CLI) |
|------|:--:|:--:|:--:|:--:|
| CVE 查询耗时 | 8 分 14 秒 | 约 72 秒 | ~5 秒 | ~5 秒 |
| 扫描总耗时 | 8 分 14 秒 | 86 秒 | - | 43 秒 |

### 2.3 仍然不达标项（新缺陷清单）

| 编号 | 严重度 | 缺陷描述 | 实测证据 |
|:--:|:--:|------|------|
| **DEF-NEW-01** | 🔴 致命 | **服务无法启动**：api/main.py 缺少 `import asyncio`（L185 NameError 崩溃） | 交付状态下 uvicorn 加载即崩 |
| **DEF-NEW-02** | 🔴 严重 | **目录输入分支绕过 Syft**：解包后走自研目录组件提取，漏掉最关键组件 busybox 1.35.0，且**所有组件版本均为 unknown** | ramdisk 识别 15 组件无 busybox；基线可识别 busybox 1.35.0 |
| **DEF-NEW-03** | 🟠 中 | **版本 unknown 导致版本约束失效**：CVE 匹配仅按组件名，存在大量历史版本漏洞误报 | 例：CVE-2017-0379（影响 libgcrypt <1.7.x）被报出，而基线确认 ramdisk 中 libgcrypt 为 1.8.5，不受影响 |
| **DEF-NEW-04** | 🟠 中 | **CVE 记录重复**：每个组件每个 CVE 按其出现文件数重复计入（114 条中实际去重后约 57 条） | libgcrypt 各 CVE 均出现 2 次 |
| **DEF-NEW-05** | 🟡 低 | 结果数据字段不完整：published_date=None、cvss_score=0.0 占比高（114 条中 56 条 severity=Unknown），R155 180 天规则依据不足 | 任务结果 JSON |
| DEF-04(遗留) | 🟡 低 | 备用合规检查器 published_date 仍用 datetime.now()（主路径已正确） | task_queue.py L515 |
| DEF-06(遗留) | 🟡 低 | config.yaml 默认值仍为 Linux 路径；/api/health 版本标识仍显示 2.4.1-hotfix | - |
