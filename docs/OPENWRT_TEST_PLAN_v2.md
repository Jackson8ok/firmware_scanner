## 三、当前阻碍与问题

### 3.1 🔴 高优先级阻碍

#### 阻碍 1: 固件类型检测不准确
**问题描述**: 
- OpenWrt 固件文件头包含自定义头部信息
- `file` 命令识别为 `firmware 444 v101 OpenWrt`，而非 `squashfs`
- 扫描器降级为 `bin` 类型，使用 MCU 提取逻辑
- 导致组件识别率为 0

**影响**:
- ❌ 无法提取 SquashFS 文件系统内容
- ❌ 组件识别失败
- ❌ CVE 匹配为 0

**当前状态**: 
- 已修改 `scanner/engine.py` 添加 SquashFS 魔数检测
- 但实测发现固件中 SquashFS 分区偏移处数据异常

**待验证**:
- [ ] 确认 SquashFS 魔数是否存在于固件中
- [ ] 确认分区偏移地址是否正确
- [ ] 验证 unsquashfs 能否直接解压

**技术方案**:
```python
# 方案 1: 魔数扫描
squashfs_magic = [b'hsqs', b'sqsh', b'shsq']
# 扫描前 1MB 查找魔数

# 方案 2: binwalk 集成
# 使用 binwalk 分析固件结构

# 方案 3: 手动指定偏移
# OpenWrt 典型结构：头部 + SquashFS (偏移 0x100000)
```

## 八、附录

### A. OpenWrt 固件结构
```
OpenWrt 固件典型结构:
├── 固件头部 (0x000000 - 0x0FFFFF)    64 字节头部 + 填充
├── SquashFS (0x100000 - 0xXXXXXX)    根文件系统
├── Kernel (可选)                      内核镜像
└── 其他分区 (可选)                    配置、日志等
```

### B. 关键命令
```bash
# 检查固件类型
file -b firmware.bin

# Binwalk 分析
binwalk firmware.bin

# 提取 SquashFS
unsquashfs -d output firmware.bin

# Syft 扫描
syft -o json firmware.bin > sbom.json

# Grype 扫描
grype -o json sbom.json > vulnerabilities.json
```
